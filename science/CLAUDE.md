# 理科シミュレーションのルール（小学校3〜6年）

このファイルは `science/` フォルダの中で作業するときに読みこまれる。全体のルールはリポジトリ直下の `CLAUDE.md` を見る。

### 置き場所とファイル

- 1つのシミュレーションは `science/` の中の1つの HTML ファイルにする（例: `science/ふりこの実験.html`）。CSS と JS も同じファイルの中に書く。今の教材と同じ形。
- ただし、ワークシート部品だけは共通ファイルにする: `science/worksheet.js` と `science/worksheet.css`。各シミュレーションからは `<script src="worksheet.js">` で読みこむ。
- 回路のつながりの判定（電流の計算・ショートの判定・つかない理由）も共通ファイルにする: `science/circuit-engine.js`。電気の単元（3年「電気の通り道」・4年「電流のはたらき」・6年「電気の利用」など）では `<script src="circuit-engine.js">` で読みこんで使い回す。部品の種類は `CircuitEngine.defineType()` で足せる。共通ファイルを直したら、使っている教材ぜんぶで動作を確かめる。
- 外部ライブラリ・CDN・画像ファイルは使わない（学校のネットワーク制限やオフラインでも動くように）。絵は Canvas か SVG でコードで描く。
- ファイル名は子ども向けの日本語にする。アドレスに `game`・`battle` を入れない（学校のフィルターで止まる）。
- 「もどる」リンクは `../index.html`。説明書は `science/○○_README.md` として同じフォルダに置く。

### 見た目

- 配色・フォント・カードの形は、今の理科教材（`science/ふりこの実験.html` など）とそろえる。
- 文字は大きく（本文18px以上）、ボタンは44px以上でタッチしやすく。
- 漢字は、その学年までに習う漢字を中心にし、ふりがなは `<ruby>` で付ける。専門用語はやさしい言い方にかえずに残し、ふりがなとやさしい説明を付ける。
- 色だけで区別しない（形・文字・もようも使う）。色覚のちがいに配慮した色にする。
- タブレットの横向き（1024×768）を基準にし、スマホの縦向きでも画面がくずれないようにする。スクロールはなるべく少なく。

### 操作

- マウスでもタッチでも動くようにする（pointer events を使う）。
- 「もういちど（リセット）」ボタンを必ず置く。
- 時間がかかる現象には「はやおくり／ふつう／ゆっくり」を付ける。
- 目に見えないもの（電気・熱・空気など）は、つぶ・矢印・色で「見える化」し、ON/OFF を切りかえられるようにする。

### 学びの流れ

- 「①予想 → ②実験 → ③結果 → ④考察」のワークシート（`science/worksheet.js`）を付ける。
- 保存には localStorage を使い、キーは「`ikechan-science-ファイル名`」にする（ほかの教材の保存データとまざらないように）。
- `?teacher=1` を付けると先生モード（ヒントと解答例）になる。

### 正しさ

- 科学的に正しい動きにする。かんたんにした部分は、画面のすみに「※じっさいとのちがい」として短く書く。
- 数値や式は学習指導要領の範囲をこえない。

### 作り方の順番

- 作る前に、画面の案（何を動かせて、何が記録されるか）を説明して、ユーザーの了承をもらう。
- 題名は子どものことばで考え、候補を3つ出して、ユーザーに選ばせる。
- 先生が改造しやすいように、コードに日本語のコメントを付ける。
- できたら内蔵ブラウザで開き、操作・リセット・タッチ・スマホ幅を確かめ、不具合を直してから報告する。

### 計画表
